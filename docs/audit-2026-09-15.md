# Project audit — 2026-09-15

## Scope and baseline

The audit started after commit `bb04927`, which contains the earlier allocation
cleanup fixes, literal fast paths, and their before/after reproductions
(documented in [oom-regressions.md](oom-regressions.md)).

Reviewed the public API and ownership model, parser and AST construction,
simplification, instruction compiler, program metadata, all three execution
engines, Unicode helpers, generated-data workflow, test drivers, benchmarks,
build configuration, CI, and usage documentation. Go reference sources were
read from the local Go 1.27.1 `src/regexp` tree.

This is a source review plus targeted runtime verification, not a proof that
all possible patterns, allocation schedules, or platforms are correct.

## Findings and before/after results

| Finding | Trigger / evidence before the fix | Result after the fix |
|---|---|---|
| High: capture names borrow caller memory | Compile `(?P<name>a)`, overwrite the source buffer; `subexpNames()[1]` changes from `name` to `xxxx` | Source copied before parsing; names and named replacement remain correct |
| High: AST depth limit can be bypassed | POSIX `a` followed by 1,000 `*` operators is accepted; Go rejects it | Returns `NestingDepth` before recursive AST passes |
| Medium: valid noncapturing nesting rejected | 1,001 nested `(?:...)` groups around `a` return `NestingDepth`; Go accepts them | Accepted; redundant parentheses do not increase AST height |
| Undefined reads in sparse indices | Fresh Pike and one-pass sparse buffers contain debug poison `0xAAAAAAAA`, then membership checks read those integers | New sparse storage initialized once; existing sparse-set reuse retained |
| Incorrect ownership documentation | Memory-model prose incorrectly groups `find` with allocated outer slices and `findIndex` with allocated index slices | Documents `find` as borrowed and `findIndex` as a value; README capture examples release their outer slices |

### Capture-name ownership

`parsePerlFlags` stores capture names as slices into its pattern argument.
Previously `compileInternal` parsed the caller's buffer and copied the source
text only afterward. Copying the source before parsing makes the AST names,
public name table, and source text share the compiled regexp's owned arena.
The regression overwrites a still-live buffer, so it reproduces the defect
without depending on a use-after-free crash. Freeing that buffer previously
left dangling capture names as well.

Test: `audit: compiled capture names own their source` in
`src/audittest.zig`. Before: `TestExpectedEqual`, expected `name`, got `xxxx`.
After: name lookup and `${name}` replacement pass.

### Parsed AST height

Counting open parentheses misses nested unary nodes in POSIX syntax and also
rejects redundant noncapturing groups. Each parsed node now caches its height;
parent construction and repetition check that height against 1,000. The check
runs before recursive repeat validation, capture collection, simplification,
and compilation. This does not add recursive height walks or change compiled
instruction semantics.

Tests in `src/audittest.zig` cover both directions. The audit corpus additionally
includes the 999/1,000 stacked-operator boundary and checks it against Go.
Existing compiler instruction-count and recursion backstops remain in place.
The port still omits Go's factoring and literal coalescing, so exact resource
limit equivalence for every possible AST shape is not claimed.

### Sparse indices

Sparse-set membership needs a defined integer to compare with the dense-set
length. Stale initialized indices are fine; undefined values in newly
allocated Zig memory are not equivalent to arbitrary initialized indices.
Pike buffers are initialized on allocation/growth, and one-pass analysis
initializes its sparse queue when constructed. Dense entries remain lazily
initialized before use.

The invariant tests in `src/exec.zig` and `src/onepass.zig` failed before the
fix with `expected 0, found 2863311530` and pass afterward. These tests
reproduce uninitialized storage, not a demonstrated end-user crash or match
mismatch. No sanitizer-based exploitability claim is made.

## Expanded verification

`tools/genaudit.go` generates `src/audit.jsonl` using Go 1.27.1. Input and
output bytes are JSON integer arrays so malformed UTF-8 is preserved exactly.
`src/auditdifftest.zig` replays 12,132 cases covering:

- Perl, `setLongest`, and actual `compilePOSIX` parsing.
- Empty, ASCII, Unicode, malformed UTF-8, and embedded NUL inputs.
- Match indices, boolean matching, all submatches, replacement, and splitting.
- Result limits `-1`, `0`, `1`, `2`, and `5`.
- Numeric/named references, duplicate names, literal dollars, malformed templates.
- Empty matches, nullable loops, alternation priority, anchors, case folding,
  character classes, and parser depth boundaries.

The exact same corpus and driver report:

```text
Before (bb04927): [audit] total=12132 failures=36
After:           [audit] total=12132 failures=0
```

The 36 differences are depth-policy cases: 12 POSIX stacked-repetition cases
and 24 redundant noncapturing-group cases in Perl/longest modes. Capture-name
ownership requires a mutable-source regression, which JSON replay alone does
not exercise.

`audittest.zig` also injects failures into compilation (including Unicode and
one-pass analysis) and public result-producing APIs. Resizing is disabled in
the backing test allocator to keep allocation indices deterministic across
Zig 0.16 and nightly arena implementations. Production allocators are unchanged.

## Reproduction commands

Current code:

```sh
zig test src/audittest.zig --test-filter 'audit:'
zig test src/exec.zig --test-filter 'audit: fresh'
zig test src/onepass.zig --test-filter 'audit: fresh'
zig test src/auditdifftest.zig --test-filter 'audit differential'
zig build test difftest fmt --summary all
zig-nightly build test difftest --summary all
```

Export the audit baseline without changing the working tree, and copy the
same public regression tests and corpus into it:

```sh
audit_before=$(mktemp -d /tmp/regex-audit-before.XXXXXX)
git archive bb04927 | tar -x -C "$audit_before"
cp src/audittest.zig src/auditdifftest.zig src/audit.jsonl "$audit_before/src/"
cd "$audit_before"
zig test src/audittest.zig --test-filter 'audit: compiled'
zig test src/audittest.zig --test-filter 'audit: POSIX'
zig test src/audittest.zig --test-filter 'audit: redundant'
zig test src/auditdifftest.zig --test-filter 'audit differential'
```

All four baseline commands are expected to fail. Run them independently if
your shell stops after the first failure.

To regenerate reference data, use the matching Go 1.27.1 toolchain and run
`tools/regen.sh`. The existing three corpora and Unicode tables were regenerated
without changes; the fourth corpus is now included in `zig build difftest`.

## Validation summary and limits

- Zig 0.16 Debug: 157/157 tests passed, including 47,839 differential cases.
- Zig 0.16 ReleaseFast: 157/157 tests and all differential cases passed.
- Zig nightly 0.17.0-dev.2131+d08989840: full differential suite and all 65
  unit/behavior tests passed.
- Formatting and whitespace checks passed.
- Generated reference results match the recorded Go 1.27.1 toolchain.

Runtime verification was performed on aarch64 macOS. CI configuration was
reviewed, but Linux CI was not run remotely during this audit. Coverage is
finite; exhaustive grammar fuzzing, cross-architecture sanitizer runs, and
exact Go resource-limit equivalence remain outside the evidence above.
Benchmark improvements such as explicit error propagation and wider workload
coverage remain follow-up work, not confirmed engine defects.
